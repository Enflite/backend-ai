# Threat model

Primary assets are credentials, sessions, proprietary documents, embeddings, model prompts/responses, internal tool access, and audit evidence. Primary adversaries include unauthenticated callers, compromised tenant users, malicious uploads, prompt-injection documents, SSRF attempts, stolen tokens, and misconfigured infrastructure.

Implemented mitigations include revocable rotating sessions with reuse detection; per-account login lockout; session inventory and log-out-everywhere; server-side RBAC, tenant, owner, model, document, classification, and tool checks; reclassification ownership/current-label/confirmation rules; `UNKNOWN = deny`; RLS defense in depth; fixed provider/tool registries; strict input schemas; list pagination; upload signature and malware boundaries; pre-vector authorization filters; untrusted-content delimiters; opaque object keys; per-user, per-route, and instance-global rate limits with faithful 429/413 responses; timeouts/cancellation; security headers; validated CORS origins (wildcards refused); audit redaction; and non-root containers.

Residual deployment risks include identity-provider configuration, TLS/key management, backup encryption, object-store policies, scanner/extractor hardening, egress controls, database role ownership, model supply-chain evaluation, incident response, retention, SIEM/OTel export, and SyteLine authorization semantics. Prompt injection is reduced, not mathematically eliminated; deployments should restrict tools, review destructive actions, and continuously evaluate models and documents. Refresh-token reuse detection is aggressive by design: concurrent legitimate refreshes racing each other can trigger a full session revocation, in which case the client must re-authenticate. The instance-level global rate ceiling is per-replica; multi-instance deployments should add a shared limiter.
